## 下一步优先级调整

此前 5 项队列/跨线程 UI 的源码风险仍真实存在，但本次 q64 已无相应拥塞证据，
不能继续靠加大队列或一口气改多个参数来优化“颗粒感”。现象更适合先做分辨率/主机增益对照：

1. 保持当前 **Dongle q64**、MAC-DV、8ms、15° 和 BLE 参数。
2. 右侧提供独立 **1600 CPI** 候选。有效配置与原 T5-03 8ms 相同，设备树只改变 cpi。
   这是测试假设，不宣称 800 CPI 一定是根因。
3. 提高 CPI 会增加同样滚球距离的位移计数，指针通常更快。先记录原 macOS 跟踪速度；
   再适当调低到相近的屏幕移动距离，观察细小移动、反向、斜线和小圆是否更容易控制。
   不强求系统滑杆正好减半，也先不改变加速度开关。
4. 若仍无改善，再区分固定物理摩擦/光学距离、macOS 增益和报告时间间隔。

macOS 调整入口：[Apple 鼠标设置](https://support.apple.com/zh-cn/guide/mac-help/mchlp1138/mac)。
如已有第三方鼠标工具，记录其设置并保持一致；不额外安装加速/平滑工具作为本次前提。
本轮不加滑动平均/插值，避免把低速颗粒感换成额外拖尾延迟。

## 备用 CAD 帧间隔统计

现有两秒汇总不能判断每个鼠标报告到达是否均匀，新增低开销直方图：

- `CAD stage=RX`：在 Dongle 已识别的右侧 input split GATT 通知中，收到 sync=true 时计数。
- `CAD stage=USB`：鼠标 HID 写端点成功返回后计数，表示本地端点接受，不是主机收到的时刻。
- 桶范围（毫秒）：`lt1` <1；`b1_6` [1,6)；`b6_10` [6,10)；`b10_14` [10,14)；
  `b14_20` [14,20)；`b20_30` [20,30)；`b30_50` [30,50)；`ge50` ≥50。
- `max_us` 含停球间隔；`max_under50_us` 只排除 ≥50ms，不代表剩下的全是持续运动。
- 每个统计窗口清零，但保留上一次到达时间；第一帧没有可统计的前间隔。
- 不打印逐帧日志，不改变采样/报告调度，不发送 HID 测试指令，不改 BLE 配对。
- 单一 input-split 轨迹球的当前硬件适用；未来增加其他 split pointing 时需区分设备。

它能区分接收帧本身是否成团，以及 USB 提交端是否额外排队；不能测端到端延迟、
推断实际无线重传，或与另一个时钟的单帧建立可靠一一对应。先不要求用户刷这份。
所有候选仍需实机验证；完整构建/校验清单见 `releases/T5-05/`。
