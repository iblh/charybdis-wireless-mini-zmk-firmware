## 相比之前改变了什么

| 改动 | 作用与证据 | 边界 |
|---|---|---|
| 单侧在线时，扫描从30ms窗口/60ms间隔改为5ms/200ms | 名义扫描占空比从50%降至2.5%，减少搜索缺席左侧对已连接右侧的干扰；用户确认r2明显改善 | 不是承诺无线报告恒定125Hz，低占空比仍可能影响接收 |
| 按0/1/2侧切换快速/后台/停止扫描，连接过程中暂停 | 保留首次发现、缺侧自动加入和断线重连；右侧自动连接/断电重连已实测通过 | 双侧实机发现与重连仍待验收 |
| 修正T5-09初始化顺序 | BLE/settings先初始化，再注册central和观察模块；避免Settings回调丢失而完全不扫描 | 原T5-09是有回归版本，已归档；r2替代它 |
| 中央位置事件队列保留64项，原来5项 | 给短时输入积压留缓冲余量 | 诊断未见队列溢出，不能将q64单独宣称为卡顿主因的修复 |
| 输出控件事件移到显示队列，Operator WPM动画改用LVGL timer | 避免输入/蓝牙回调直接操作这些LVGL对象，减少线程竞争风险 | 本地真实LVGL回归通过，未单独测量其对实机延迟的贡献 |
| 右侧延迟样本不再清空未上报位移，定点旋转保留小数，报告门限8ms | 避免迟到时丢掉累计运动，保留15°方向校正和慢速小位移 | 这些属于此前右侧更新，r2本次只改变Dongle；8ms是报告门限而非空口保证 |
| 正常Dongle关闭临时链路诊断，启动顺序校验进入本地构建与CI | 减少日用诊断负担，防止只通过编译却漏掉实际启动顺序回归 | CI已增加检查，远程运行状态需另行核实 |

因果依据来自T5-08的同连接ON/OFF/OFF/ON实验：RX 30–50ms间隔合并占比
从9.542%降至0.462%，HCI≥30ms长尾同步明显减少，PMW源端节奏基本稳定。
**该数字描述关扫描对照，不是对r2重新采样的数字。** r2目前的效果证据为用户实机反馈。
完整数据和统计口径见 [扫描A/B结果](24-scan-ab-results-and-fix.md)。

未采用的调整：1600 CPI没有改善卡顿且偏快，已回到800；ATT8没有明确端到端收益，保留ATT3。
不再反复调这两项，也不同时更改PHY、连接间隔和多个缓冲来猜测原因。

## 后续优先级与可执行任务

1. **右侧日用版收敛（待开发）。** 把方向校正、分数累计、迟到样本保留和8ms调度从诊断统计中独立出来，
   再关闭ATT/HCI包装、周期日志和大日志缓冲。先验证净位移/方向/小位移行为一致，再做短时单变量实机比较。
   当前不能宣称关闭统计必然更顺滑或续航提高多少；用户可以继续使用现有组合。
2. **双侧与长时间使用验收（待实测）。** 双侧自动加入，分别断电重连；连续打字/滚球/切屏，
   再覆盖macOS、Windows USB切换和休眠唤醒。单侧通过不代表这些场景都完成。
3. **鼠标操作的日用可达性（待用户验收/设计）。** 先验证现有NAV中的左右键、SCROLL和SLOW、拖拽，
   再考虑右手可独立操作的入口、滚动锁定或中键；现有RIGHT TEST是实验键位，不作为默认直接合入。
4. **仅在仍有明显问题时继续性能测量。** 保持当前参数，针对持续慢速匀速动作采一次轻量帧间隔统计，
   先区分光学丢追踪与RX/USB空档；不要求现在再做完整诊断轮次。

暂不加入默认滤波/插值：它可能以延迟和细节损失换取视觉平滑，当前应先保留真实响应。
不修改传感器供电、接线、充电电路或已经打印的外壳。
